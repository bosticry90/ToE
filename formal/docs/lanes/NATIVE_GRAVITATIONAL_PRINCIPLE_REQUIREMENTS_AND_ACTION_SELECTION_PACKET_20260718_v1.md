## Seven matrix cell states

Every completed cell uses one value:

```text
AFFIRMATIVELY_SATISFIES_REQUIREMENT
ELIMINATED
NOT_DECIDABLE_FROM_REQUIREMENT
OUTSIDE_FROZEN_ENVELOPE
EQUIVALENT_UNDER_LOCAL_BULK_RULE
REQUIRES_SUPPLIED_ASSUMPTION
NOT_EVALUATED
```

Semantics:

- `AFFIRMATIVELY_SATISFIES_REQUIREMENT` requires bound evidence of
  compatibility.
- `ELIMINATED` requires a derivation or counterexample and an eligible native
  requirement in the native-only pass.
- `NOT_DECIDABLE_FROM_REQUIREMENT` is a completed epistemic result. It creates
  an unresolved family, not an affirmative survivor.
- `OUTSIDE_FROZEN_ENVELOPE` is a scope classification, not elimination.
- `EQUIVALENT_UNDER_LOCAL_BULK_RULE` requires a registered equivalence proof.
- `REQUIRES_SUPPLIED_ASSUMPTION` cannot influence native selection.
- `NOT_EVALUATED` makes the production analysis incomplete and blocks a
  scientific terminal result.

The evaluator never infers affirmative compatibility from absence of an
elimination result.

## One bounded production path

The shared entry point is:

```text
evaluate_analysis(analysis_input)
```

Its fixed sequence is:

```text
validate requirement identity and statement class
-> validate source/class compatibility
-> validate family identity and envelope status
-> validate complete matrix shape and cell vocabulary
-> exclude supplied-assumption effects from native selection
-> validate and apply local-bulk equivalence map
-> compute eliminated, affirmative, and unresolved family sets
-> evaluate native discriminating requirement trace
-> evaluate distinctiveness and exhaustion evidence
-> select exactly one production result
```

The evaluator is table-driven. It performs no symbolic variation and does not
enumerate theories.

## Family-set semantics

For primary-envelope families:

- any eligible native `ELIMINATED` cell places the family in the eliminated set;
- if no eliminating cell exists but at least one applicable cell is
  `NOT_DECIDABLE_FROM_REQUIREMENT` or `REQUIRES_SUPPLIED_ASSUMPTION`, the family
  is unresolved;
- a family is affirmative only when every applicable native requirement has an
  affirmative or registered-equivalence disposition and no cell is unresolved,
  eliminated, or unevaluated;
- supplied-assumption eliminations are recorded in a conditional trace but do
  not change native sets.

Outside-envelope families remain outside all native survivor counts.

## Disjoint production result logic

Internal non-scientific failures occur before the six scientific outcomes:

```text
PRECHECK_FAILURE
ANALYSIS_INCOMPLETE
EMPTY_SET_CLASSIFICATION_INSUFFICIENT
```

Once preflight and matrix completion pass, production uses one ordered
`if / elif` decision with disjoint predicates.

### No primary family remains

- `REQUIREMENT_SET_INCONSISTENT` requires an explicit inconsistent accepted
  subset and an empty possible-family set.
- `NO_GO_UNDER_MINIMAL_METRIC_LOCAL_ASSUMPTIONS` requires that consistent
  gravitational families exist but a bound proof excludes the desired
  distinctiveness within the frozen class.
- Without either proof, return the internal
  `EMPTY_SET_CLASSIFICATION_INSUFFICIENT`; do not guess a scientific outcome.

### Exactly one local-bulk equivalence class remains

- Return `CURRENT_REQUIREMENTS_COLLAPSE_TO_STANDARD_GR` when the class is
  `F_EH`, no native discriminating trace establishes project-specific
  distinctiveness, and no unresolved primary family remains.
- Return `NATIVE_PRINCIPLE_SET_SELECTS_ACTION_FAMILY` only when at least one
  eligible project-bound requirement demonstrably eliminates an inequivalent
  alternative, the remaining class is unique, and at least one frozen
  distinctiveness test is established.
- A unique non-EH class lacking that evidence remains
  `ACTION_FAMILY_UNDERDETERMINED`; mere table shape is not native selection.

These predicates are disjoint by construction.

### Multiple or unresolved classes remain

- Return `DISTINCTIVE_GRAVITATIONAL_POSTULATE_REQUIRED` only when the complete
  accepted native inventory is verified exhausted and a bound countermodel or
  equivalent proof shows that no refinement latent in that inventory can
  distinguish the remaining classes.
- Otherwise return `ACTION_FAMILY_UNDERDETERMINED`.

The result includes `matching_scientific_outcome_count = 1`. Any internal
overlap is a production failure.

## Local-bulk equivalence

The v0 rules are unchanged. Equivalence requires a registered proof and may
cover algebraic identities, compact-support-trivial divergences,
four-dimensional local-bulk topological terms, admissible invertible local
field redefinitions, or consistently transformed normalizations.

It may not merge different propagating modes, derivative order, source
coupling, locality, independent variables, observable coefficients, signs,
indices, or boundary conditions.

## Eight production controls

All controls call `evaluate_analysis`.

| ID | Atomic mutation or fixture | Required production result |
| --- | --- | --- |
| `CTRL_SUPPLIED_SECOND_ORDER_NOT_NATIVE` | supplied second-order row eliminates one family | native result remains `ACTION_FAMILY_UNDERDETERMINED`; trace records supplied exclusion |
| `CTRL_MISSING_STATEMENT_CLASS` | remove one row's class | `MISSING_STATEMENT_CLASS` before matrix evaluation |
| `CTRL_DUPLICATE_REQUIREMENT` | duplicate one canonical requirement | `DUPLICATE_CANONICAL_REQUIREMENT` before matrix evaluation |
| `CTRL_SHARED_NEWTONIAN_LIMIT` | two inequivalent families affirmatively satisfy only Newton–Poisson | `ACTION_FAMILY_UNDERDETERMINED` |
| `CTRL_UNDECIDABLE_CELL` | replace one affirmative cell with undecidable | family enters unresolved set, never affirmative set |
| `CTRL_BOUNDARY_EQUIVALENCE` | add one boundary-equivalent `F_EH` representative | one local-bulk class and `CURRENT_REQUIREMENTS_COLLAPSE_TO_STANDARD_GR` |
| `CTRL_UNIQUE_NONDISTINCTIVE_EH` | only `F_EH` remains without native distinctiveness | `CURRENT_REQUIREMENTS_COLLAPSE_TO_STANDARD_GR` only |
| `CTRL_UNIQUE_NATIVE_DISTINCTIVE` | one eligible native requirement uniquely eliminates an inequivalent family and distinctiveness is bound | `NATIVE_PRINCIPLE_SET_SELECTS_ACTION_FAMILY` only |

Each control changes one premise relative to its registered positive fixture or
uses one minimal synthetic fixture. Expected outcomes are computed from the
production result, not hard-coded pass flags.
