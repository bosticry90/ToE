## Blocking finding 1: project evidence can self-attest

For each evidence record, V2 accepts a caller-selected validator identifier,
an `ACCEPTED` string, a caller-authored attestation, and matching file hashes.
The catalog manifest similarly accepts a caller-authored
`ACCEPTED_FOR_BOUNDED_ANALYSIS` field. The implementation checks that these
objects agree with one another; it does not obtain the acceptance decision from
an independent authority.

Consequently one actor can manufacture all four roles:

```text
evidence producer
scientific assessor
contract validator
catalog authority reviewer
```

The hashes prove only that the manufactured bundle is stable. They do not prove
that its scientific conclusion is supported.

Diagnostic:
`PROJECT_EVIDENCE_PROVIDER_SELF_ATTESTATION_ACCEPTED`

## Blocking finding 2: scientific relevance is not validated

The accepted validator identifiers are closed strings, but there is no
validator dispatch, scientific predicate, derivation checker, or reviewed
assessment result behind them. The project-provider preflight validates that:

- the record names the expected validator class;
- the attestation repeats the same validator identifier and claim binding;
- the referenced source exists inside the repository;
- the recorded hashes match the bytes.

It does not validate that the source concerns the exact family, proves the
exact requirement relationship, supports the requested status, or has an
adequate physical and mathematical domain. The irrelevant-source probe passed
all production checks, which is direct evidence that semantic relevance is not
enforced.

Diagnostic:
`SCIENTIFIC_RELEVANCE_VALIDATOR_NOT_EXECUTED`

## Blocking finding 3: synthetic controls bypass project-provider validation

The retained, boundary, adversarial, and six-outcome controls all call the
function identified as `evaluate_analysis_v2`. That shared entry point is real,
but it is not the whole path-integrity question.

Control fixtures use `INTERNAL_SYNTHETIC_CONTROL_PROVIDER_V2`. The control
branch accepts that in-memory provider by exact object equality. Its records
use synthetic references and omit the project validator, source-hash,
attestation, and manifest requirements. Future real analysis takes a different
project-provider branch.

Thus the controls exercise the common matrix reducer and terminal classifier,
but not the evidence-provider path that failed the production-profile probe.
The packet's claim that controls and future analysis share the production path
is materially overstated.

Diagnostic:
`SYNTHETIC_CONTROLS_BYPASS_PROJECT_PROVIDER_VALIDATION`

## Blocking finding 4: authority custody is not revalidated per evaluation

V2 validates frozen source hashes while generating the preparation packet.
`evaluate_analysis`, however, does not invoke that custody validator. It reads
module-global bound catalogs after only checking submitted identifiers.

Frozen dataclasses and mapping proxies prevent ordinary field mutation, which
is a retained success. They do not make module-global bindings unreplaceable,
nor do they detect an upstream authority change after module import. A
production scientific evaluation therefore lacks its own authority-custody
precondition.

Diagnostic:
`PRODUCTION_AUTHORITY_CUSTODY_NOT_REVALIDATED`
