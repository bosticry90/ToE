## Integration Read

The project already uses computation in the right epistemic role: as an executable consequence engine, falsification surface, reproducibility surface, and claim-boundary control. The next improvement should not be "more simulations first." It should be a credibility wrapper around the simulations and numerical artifacts that already exist.

The main integration target is therefore:

> Every computational artifact should be classifiable by what it verifies, what it validates, what uncertainty it carries, what robustness scans it has survived, what regime limit it addresses, what falsifier it exposes, and what claim label it is allowed to support.

This keeps the existing ToE posture intact: computation can support `E-REPRO`, comparator design, sensitivity pressure, and bounded retain/prune/inconclusive decisions; it cannot promote `T-LEAN-*`, empirical adequacy, seam closure, or master-action status by itself.

## Roadmap Phases

### Phase 0: Policy Attachment

Outcome:
- Bind computational-physics expansion to the existing auxiliary nonclaim computational-analysis lane.

Required work:
- Keep all computational-physics additions under `AUXILIARY_NONCLAIM_COMPUTATIONAL_ANALYSIS` unless a later front-door authorization explicitly upgrades them.
- Require every new computational-physics surface to state whether it is verification, validation, UQ, robustness, model comparison, known-limit recovery, or falsifier design.
- Require every new surface to carry an explicit claim ceiling.

Exit criteria:
- `COMPUTATIONAL_PHYSICS_INTEGRATION_ROADMAP_v0` is pinned in `PHYSICS_ROADMAP_v0`.
- The focused roadmap gate passes.

### Phase 1: Capability Audit First

First packet:
- `COMPUTATIONAL_PHYSICS_CAPABILITY_AUDIT_v0`

Recommended location:
- `formal/docs/paper/COMPUTATIONAL_PHYSICS_CAPABILITY_AUDIT_REPORT_v0.md`
- Optional machine-readable mirror: `formal/docs/release/COMPUTATIONAL_PHYSICS_CAPABILITY_AUDIT_20260515_v0.json`

Purpose:
- Classify current ToE computational artifacts by capability rather than by ambition.

Required categories:
- simulation: `none`, `exploratory`, `verified`, `validated`
- verification: `missing`, `unit`, `convergence`, `MMS`, `independent`
- validation: `none`, `known_limit`, `empirical`, `predictive`
- UQ: `none`, `qualitative`, `quantitative`
- robustness: `none`, `partial`, `full_scan`
- regime recovery: `none`, `conditional`, `derived`
- falsifier: `absent`, `defined`, `executed`, `passed`, `failed`, `blocked`
- claim boundary: `unclear`, `stated`, `enforced`

Audit questions:
- What computational-physics capabilities are already present?
- Which results are verification-only?
- Which results are validation-relevant but not yet validated?
- Which claims require UQ before any public-facing upgrade?
- Which artifacts are public-presentation ready?
- Which artifacts must remain internal or research-only?

Claim ceiling:
- Capability classification only.
- No blocker movement, no validation claim, no promotion.

## Definition Of Done

This roadmap is integrated when:
- it is pinned in `PHYSICS_ROADMAP_v0`;
- its focused gate passes;
- future computational-physics packets bind to the existing auxiliary nonclaim computational-analysis policy;
- the first follow-up packet is the capability audit, not a new physics domain;
- no release-facing claim label is upgraded by this roadmap alone.

The first follow-up packet is complete when:
- current computational artifacts are inventoried;
- each artifact receives verification, validation, UQ, robustness, regime-recovery, falsifier, and claim-boundary fields;
- every row has a claim ceiling;
- public-ready versus internal-only status is stated;
- the audit result remains nonclaim unless a separate authorization surface says otherwise.
